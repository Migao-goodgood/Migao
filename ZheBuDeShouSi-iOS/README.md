# 这不得瘦死 · iOS / iPadOS / macOS

这是原微信小程序的原生 SwiftUI 重写版，最低支持 iOS 26、iPadOS 26 和 macOS 26。

## 打开

用 Xcode 打开 `ZheBuDeShouSi.xcodeproj`，选择 iPhone/iPad 模拟器、真机或 Mac 后运行。第一次真机运行需要在 Xcode 的 Signing & Capabilities 中选择自己的 Apple Developer Team。

## TestFlight

本次版本的中文测试说明位于 `TestFlight/WhatToTest.zh-Hans.txt`。Xcode Cloud 上传 TestFlight 构建时会读取这个与 `ZheBuDeShouSi.xcodeproj` 同级的文件，并自动填写简体中文“测试内容”；它采用静态维护方式，每次正式构建前更新并提交即可。如果使用本机 Organizer 上传，也可以在上传页面的 “What to Test” 中直接粘贴文件内容。

## 发布流程

每次正式发布必须按此顺序执行：先读取根目录 `ARCHITECTURE.md`，拉取并确认未落后 `origin/main`；更新 App 版本、递增整数构建号及 `TestFlight/WhatToTest.zh-Hans.txt`；完成统一编译；在提交正文中写入用户可见修改、验证结果与已知限制；推送 `main` 后再创建并推送带说明的版本标签。

```bash
git push origin main
git tag -a vX.Y.Z -m "Release vX.Y.Z"
git push origin vX.Y.Z
```

最后使用 `git ls-remote` 核对远端 `main` 与版本标签都指向预期提交。禁止覆盖已有标签或强制推送。

版本号采用语义化规则：兼容的 UI 调整和修复递增补丁号，新用户功能递增次版本号，不兼容的产品或数据变更才递增主版本号。每次上传的 Xcode 整数构建号在上一构建基础上加一，由维护流程自动决定，无需人工询问。

macOS 的 App Store Connect 导出配置位于 `Distribution/ExportOptions-mac-app-store.plist`，命令行导出时使用该路径。

## 已包含

- 全新安装不包含任何演示体重、目标、饮水、活动、饮食或 InBody 数据；所有内容均由用户本地记录或主动授权 Apple 健康后产生
- 首次体重记录自动成为起点和当前体重；目标体重必须由用户自行设置，未设置时首页和“我的”不显示虚构数字
- 首页、饮食、趋势、我的四页底部导航
- 首页轻盈进度、当前体重、目标体重和体重日历
- 首页只保留一个“今日饮食”轻入口，显示当天 kcal / 餐数并直达饮食日记
- 饮食日记：日历 / 图谱双视图、每日 kcal 汇总、照片拼贴和中央审核弹窗
- 饮食详情弹窗的上传入口位于内容上方，支持每批多选照片并重复追加，不覆盖当天已有餐食
- 饮食照片默认使用设备端文字识别读取可见餐名或 kcal；识别结果必须人工确认后才计入汇总
- 轻盈进度卡片平日保持简洁；二十四节气当天显示节气名和《月令七十二候集解》短句
- 体重使用主题色卡尺式滑动选择器，可在“公斤 / 斤”间切换；历史值统一按公斤保存，`1 公斤 = 2 斤`
- 记录体重时可通过日期滚轮补录最近两年的日期，记录弹窗标题居中且主按钮为“保存”
- “我的”页提供全局体重单位设置，切换“公斤 / 斤”后首页、日历和趋势同步更新
- 居中的统一记录弹窗；体围继续使用双列滚轮并精确到 0.1 cm，体重/目标体重卡尺每格为 0.1 公斤（切换为斤时等价显示为 0.2 斤）
- 饮食、饮水和运动记录保留适合各自单位的文本输入
- 首页体重趋势预览点击后打开中部趋势弹窗；图表区域可左右滑动查看长周期数据，不切换底部页面
- 首页体重记录改为“体重日历”：按月份和日期网格展示每天最新体重，仅显示一位小数数字；同日多次记录取当天最新值，升高加深、降低变浅
- 轻盈进度条下方左侧用实线下括号显示“已减”（当前−起点），右侧用虚线数学下括号显示“距离目标体重还差”（终点−当前）
- “体重趋势”和“体重日历”使用与趋势页“身体趋势”一致的横向四字标题样式；标题旁不再放竖向分隔线
- “我的”页点击“关于这不得瘦死”会在页面中央显示一条日文寄语，可点击关闭
- 身体数据工作区：InBody 报告照片上传、自动设备端识别/可选后端 AI 分析、人工核对、上次/首次对比、四项核心趋势和历史详情
- InBody 定期测量：支持 2/4/6/8 周周期，用户开启通知权限后按最新报告日期安排系统提醒
- 体围记录：腰围、臀围、左右上臂围、左右大腿围、左右小腿围及独立趋势图
- 旧习惯记录仍保留在本地数据层用于兼容，但主导航已由“习惯”切换为“饮食日记”
- Apple 健康连接：授权后导入最近 90 天体重、腰围、饮食热量、饮水、运动、睡眠和生理期；饮食热量进入饮食日记并按 HealthKit 样本 ID 去重
- UserDefaults 本地保存体重、饮水、活动和趋势历史

## Apple 健康

在 iPhone 上进入“我的” -> “Apple 健康” -> “连接”，在系统弹窗中允许读取需要的项目。导入只读，不会修改 Apple 健康；本地手动记录仍然保留。臀围、上臂、大腿、小腿、排便和吃药没有稳定的通用 HealthKit 数值，继续在应用内手动记录。

Apple 健康中的饮食能量样本会作为来源标记为“Apple 健康”的饮食记录显示在日历和图谱中；同一 HealthKit 样本重复同步不会重复计入。照片识别和手动录入仍然需要在饮食页逐条确认。

macOS 版本使用原生 SwiftUI 窗口运行，输入框会自动使用 macOS 的文本输入行为；iOS/iPadOS 版本保留数字键盘和滚轮选择器交互。iPadOS 和 macOS 会将主要内容限制在居中的宽度内，便于宽屏阅读。

## 身体数据

“趋势”页现在是专门的 InBody 身体数据模块，三维形象和形象切换已移除。右上角“上传”从相册选择纸质报告照片，随后自动分析并打开可编辑核对表单；只有用户确认的数据才会进入历史和趋势。页面同时提供与上次/首次测量对比，以及体重、体脂率、体脂肪量、骨骼肌量四项趋势。默认使用设备端 Vision OCR，不上传照片；仓库目前没有预置 AI 地址。配置 `INBODY_AI_ENDPOINT` 后，可由自有 HTTPS 后端调用 GPT 或其他视觉模型，但每次发送健康报告前都会征求同意，并允许改用设备端识别。客户端不保存 API key，后端失败会回退本地识别。

核对表单支持测量日期、身高、年龄、性别、设备型号、核心身体成分，以及总体水分、蛋白质、矿物质、去脂体重、身体细胞量、基础代谢率和 SMI。识别不出的字段保持为空，不会推测；原始照片在分析完成后从内存释放，不写入本地历史。阶段分析只描述已确认数据的变化，不提供医学诊断。定期测量默认关闭；开启后才请求系统通知权限，并根据最新测量日期安排下一次提醒。

## 微信登录

“我的”页当前不展示微信登录入口；头像仍支持从系统相册选择并保存在本地。微信授权协调器和回调校验代码保留在独立功能目录中，后续重新开放入口时仍需要微信开放平台 AppID、URL Scheme（或 Universal Link）、服务端 code 换 token，以及短期一次性 `ticket/session` 回调。AppSecret、访问令牌和跨设备账号同步必须留在服务端，不能放进 iOS 包。

## 目录

- `ZheBuDeShouSi/App`：App 入口、Info.plist 和签名 entitlements
- `ZheBuDeShouSi/Shared`：跨平台模型与 SwiftUI 界面
- `ZheBuDeShouSi/Features`：健康数据和 Apple 健康功能
- `ZheBuDeShouSi/Resources`：AppIcon 和其他资源
- `Distribution`：归档导出配置
- `TestFlight`：TestFlight 测试说明
